# 치명도 · 증거 수준 · 보고 서식

발견마다 **두 칸을 따로** 적는다 — **등급**(얼마나 아픈가)과 **증거**(얼마나 확실한가).
예전에는 «잠재» 를 등급 칸에 넣었다. 그러면 «아프지만 확실하지 않은 것» 과 «덜 아프지만 확실한 것» 이 섞인다.
AI 조사원은 스스로 확인하지 않은 판단이 쉽게 흔들린다(이름만 바꿔도 결론이 바뀐다는 연구가 있다) — 그래서 증거 칸이 따로 있어야 한다.

## 등급 — 얼마나 아픈가

등급은 **«도달 가능성 × 되돌릴 수 있나 × 알아챌 수 있나»** 세 가지로 정한다(FMEA 의 발생도·심각도·검출도와 같은 구조).
«어렵고 복잡해 보인다» 는 등급의 근거가 아니다.

| 등급 | 뜻 | 보기 |
|---|---|---|
| **치명 C** | 평범한 사용으로 도달하고, 데이터가 조용히 틀어지거나 남의 자료가 새고, **되돌리기 어렵다** | 이중 차감, 남의 개인정보 노출, 결제 중복, 지워지면 끝인 데이터 삭제 |
| **높음 H** | 도달 가능하고 피해가 실질적이지만, 알아챌 수 있거나 손으로 복구 가능 | 특정 경로에서 검증 누락, 스위치 껐는데 검색에 노출, 알림 이중 발송 |
| **중간 M** | 도달 경로가 특수하거나(관리자만·희귀 조건), 곧 눈에 띈다 | 경계값 계산 오차, 고아 행 누적, 오류 메시지 부정확 |
| **낮음 L** | 불편·일관성·정리 | 문구 불일치, 죽은 코드, 중복된 유틸 |

## 증거 — 얼마나 확실한가

| 증거 | 뜻 | 요구하는 것 |
|---|---|---|
| **E3 재현됨** | 실제로 돌려서 그 결과가 났다 | 실행 기록(명령·요청과 결과) 또는 실패하는 시험 경로. «X 를 했더니 Y 가 나왔다» 꼴 |
| **E2 코드로 확인** | 입구부터 문제 줄까지 경로를 코드 줄로 짚었다 | 파일:줄 사슬. 돌려 보지는 못했다 |
| **E1 미검증** | 위험해 보이나 경로를 다 짚지 못했다 | 왜 확인 못 했는지 한 줄. 예전 «잠재» 가 여기다 |

- **E3 는 찾은 조사원이 아닌 다른 검증자가 매긴다** — 새 문맥에서, 발견 설명만 받고 직접 돌려 본다(SKILL.md «검증»).
  찾은 사람의 확인은 E2 까지만 센다. 스스로 다시 읽어 보는 것은 검증이 아니다.
- **«문제 없음» 판정에도 증거를 적는다** — «악용할 수 없다», «도달하지 않는다» 도 E2 이상이어야 한다.
- 보고서에서 **E1 은 따로 묶는다.** 등급이 치명이어도 E1 이면 «확인할 것» 목록이지 «고칠 것» 목록이 아니다.
- **«이래야 한다» 의 출처가 없으면 E1 «가정한 요구»** 다 — 특히 기획자 시선. 규칙 문서·화면 문구·사람의 말 중 무엇에서 온 요구인지 인용한다.
- **인용이 실재해야 E2** — 적힌 파일·줄·함수 이름이 실제로 있어야 한다(`audit-check` 가 기계로 확인). 없으면 E1 로 내린다.
- **증거를 올렸다 내리지 않는다.** 올렸다가 내리면 검수 전체의 신뢰가 깎인다(내릴 일이 생기면 «정정» 으로 밝힌다).

## 상태 (사람이 정한다)

| 상태 | 뜻 |
|---|---|
| **열림** | 찾았고 아직 결정 전 |
| **고침** | 이번에 고쳤다 — 재현 시험 경로와, 그 시험이 **고치기 전 코드에서 실패하는 것**을 확인한 사실을 함께 적는다 |
| **정책** | 의도적으로 그렇게 둔 것 — 버그가 아니다. **이유와 만료일**(기본 90일)을 적는다. 만료되면 다시 «열림» 으로 본다. **치명은 정책으로 둘 수 없다** |
| **보류** | 인정하지만 지금은 안 고친다 — 왜, 그리고 무엇이 트리거가 되면 고칠지 |
| **사람이 실행** | 데이터 정리 등 자동으로 하면 안 되는 것 — 관리자 화면·스크립트를 만들어 넘겼다 |
| **다시 열림** | «고침» 이었는데 다음 검수에서 같은 지문으로 또 나왔다 |
| **기각** | **틀린 발견**(오탐)이다 — 반박 점검에서 걸렸거나 재현되지 않고 반증이 있다. **반증**(이미 막고 있는 줄·실제 규칙의 출처·재현 실패 기록)을 적는다. 다음 검수에서 같은 지문이 나오면 새로 올리지 않고 여기에 붙인다 |

«정책» 과 «기각» 을 섞지 않는다 — 정책은 «맞는 지적인데 일부러 둔다», 기각은 «지적이 틀렸다». 섞으면 적중률이 거짓말을 한다.

## 발견 번호와 지문 — 다음 검수와 이어 붙이기

- 발견마다 **고정 번호**를 준다(`F-0001`). 번호는 다시 쓰지 않는다. 등급 글자(C1·H2)는 회차마다 바뀌므로 번호로 쓰지 않는다.
- **지문**: `축 · 구역 · 파일 · 함수(또는 화면) · 한 줄 요약`. 다음 검수에서 같은 지문이 나오면 새 번호를 만들지 않고 **이어 붙인다**
  (줄 번호는 바뀌므로 지문에 넣지 않는다).
- 발견 대장(`docs/audit/FINDINGS.md`, 서식 `templates/FINDINGS.md`)은 **줄을 지우지 않고 이력만 더한다**.

## 항목 서식

항목마다 아래를 모두 적는다. 하나라도 비면 그 항목은 아직 **검수가 끝난 것이 아니다**.

```
### [F-0012] 한 줄 제목 — 등급 H · 증거 E3 · 시선: 운영자 · 축: 5 불변식 / 구역: 휴가
- **도달 경로**: 어떤 사람이 어떤 화면·API 에서 무엇을 하면 닿는가 (구체적으로)
- **증거**: E3 — 실행 기록·시험 경로 / E2 — 파일:줄 사슬 / E1 — 왜 확인 못 했나
- **피해**: 무엇이 틀어지나 · 되돌릴 수 있나 · 알아챌 수 있나
- **제안**: 어디를 어떻게 (한 곳에서 막는 방법 우선) · 노력 S/M/L
- **상태**: 열림 / 고침 / 정책(만료일) / 보류 / 사람이 실행
```

## 보고할 때

- **커버리지를 맨 위에** — 시선 × 축 × 구역 중 훑은 칸 / 일부만 본 칸 / 안 본 칸 / 해당 없음, 그리고 **건너뛴 점검과 이유**.
  안 본 칸을 숨기면 «검수 완료» 가 거짓말이 된다
- 첫 줄에 **검수 방식(간편/정밀)과 안 본 것** — `modes.md`
- 그다음 **등급 순, 개수 먼저.** «치명 1 · 높음 4 · 중간 7 · 낮음 3 (그중 E1 2) · 기각 3»
- **«먼저 결정해 주실 것» 은 치명·높음이면서 E2 이상만, 최대 `reportTop`(기본 7)개.** 나머지는 부록으로 접는다.
  사소한 지적 20개 사이에 진짜 1개가 묻히는 것이 AI 검수의 가장 흔한 불만이다
- 서식·이름 같은 기계적 지적은 보고에 올리지 말고 linter·포매터 규칙으로 넘긴다
- 치명·높음은 **무엇을 하면 되는지**까지 한 줄로. 중간 이하는 목록으로 충분하다
- 고칠 순서는 **등급 → 노력(S 먼저) → 같은 파일끼리 묶기**
- **고칠지 말지는 사람이 정한다.** 검수자는 «고쳤습니다» 가 아니라 «이런 것이 있습니다» 를 먼저 낸다
  (다만 명백한 치명 + 고치는 범위가 분명하면 고쳐서 함께 보고해도 된다)
- 정정이 생기면 **정정 항목을 따로 밝힌다** — 조용히 고쳐 쓰지 않는다
- **보안 발견은 공개 이슈·공개 댓글에 올리지 않는다** — 사람에게 직접 건넨다

## 흔한 함정

- **개수 부풀리기**: 같은 원인 하나를 화면 수만큼 나눠 적지 않는다. 원인 1개 = 항목 1개, 영향 범위를 안에 적는다
- **«리팩터링하면 좋겠다» 를 버그로 올리기**: 그건 낮음이거나 검수 밖이다
- **증거 없이 «위험해 보임»**: E1 로 두고 «확인할 것» 에 넣는다
- **고치면서 훑기**: 훑기가 끊기고 목록이 비뚤어진다. 찾는 일과 고치는 일을 나눈다
- **AI 가 스스로 매긴 확신 점수(0~100)를 증거로 쓰기**: 점수는 같은 머리의 자기 평가다. 증거는 실행 결과와 코드 줄뿐이다
- **«0개가 될 때까지 반복»**: 같은 모델이 같은 머리로 다시 보는 고리는 끝나는 조건이 자기 판정이다. 대신 시선을 바꾸고 검증자를 바꾼다
