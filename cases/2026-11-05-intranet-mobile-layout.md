# 폰에서 탭 줄이 줄바꿈되고, 넓은 표가 옆 칸에서 잘렸다 — 2026-11-05

| | |
|---|---|
| **프로젝트 성격** | 사내 업무 시스템 (관리자·직원이 주로 폰으로 씀, 앱 안 브라우저·홈 화면 앱) |
| **축** | 24 클라이언트·화면 (새 축) · 20 표현 |
| **시선** | 퍼블리셔 · 고객 |
| **등급** | 중간 |

## 무엇을 어떻게 찾았나
여러 차례 **사용자가 직접** 캡처를 보내 알렸다 — 개발자 시선의 검수로는 하나도 나오지 않았다.
그 뒤 «화면 × 너비(390·820·1280) × 가로 넘침 수치» 표를 만들어 재 보니 같은 종류가 더 나왔다.
- 상단 탭·버튼 줄이 좁은 화면에서 **줄바꿈되며 큰 여백**이 생겼다.
- 직원 관리 카드에서 버튼 배치가 깨졌다.
- 두 칸 배치의 좁은 쪽에 8칸짜리 기록 표를 넣어, PC 에서 표가 **옆으로 잘리고** 마지막 칸(수정·삭제 버튼)이 가려졌다 — 측정값 `scrollWidth 911 > clientWidth 572`.

## 왜 시험이 못 잡았나
시험은 서버 응답(200·리다이렉트)과 데이터만 봤다. 화면은 «그려지면 통과» 였고 **그려진 모양**을 재는 시험이 없었다.
검수의 축은 모두 서버·데이터 방향이라, 퍼블리셔의 눈으로 보는 자리가 아예 없었다.

## 어떻게 막았나
- 넓은 표가 들어가는 상세 화면은 위아래로 쌓는 배치로 바꿈.
- 바뀐 화면마다 너비 390·1280 캡처 + `scrollWidth ≤ innerWidth` 를 확인한 뒤에만 올림.
- 화면 규격(높이·간격·둥글기·색)은 디자인 토큰 한 곳에서만 고치게.

## 다른 프로젝트에 옮길 수 있는 교훈
- **화면 문제를 사용자가 먼저 찾는다면 퍼블리셔 시선이 비어 있는 것이다.** 화면 × 너비 표를 만들고 **눈이 아니라 수치(가로 넘침)** 로 잰다.
- 두 칸 배치 안의 넓은 표는 거의 항상 잘린다 — 표가 들어가는 칸의 최소 폭을 먼저 잰다.
